# 落とし穴（ペカり君）

踏んだ失敗・守るべき仕様を、版を付けて1節ずつ足す。共通のものは `GOTCHAS_GENERAL.md`。

## 1. 読み込み順と関数の巻き上げ（1.16.1 の分割で整理）
- 旧 `app.js` は1ファイルだったので、どの関数もファイルの先頭に巻き上げられていた。分割後は**ファイルをまたぐと巻き上げられない**。
- そのため、ファイルのトップレベルで即実行する処理（例：`settings.js` の `applySettings()`、`display.js` の `syncTapHint()`、`modal.js` の `refreshRateLabel()`）が呼ぶ関数は、**同じファイル内か、それより前に読み込むファイルで定義されている**必要がある。
- 関数の中から呼ぶだけ（クリック時など後で呼ばれる）なら、後ろのファイルで定義されていても問題ない。
- 新しい即実行処理を書いたら、起動直後にエラーが出ないか（pageerror 0件）を必ず確認する。

## 2. 同じ名前の再宣言
- 全ファイルでグローバル共有なので、`const X` を2つのファイルに書くと読み込み時にエラーになる。新しい定数は `JS/data/config.js` に足すと探しやすい。

## 3. 画像・音声のパス
- 画像は `ASSET_DIR.img`、音声は `ASSET_DIR.sound` を通す。ファイル名や場所を直書きしない（`reels.js` と `reel-view.js` の `<img>` 生成、`audio.js` の `SOUND_FILES`）。

## 4. 保存キー
- `pekari-settings-v5` などの保存キーは変えない（`PROJECT_CONTEXT.md` の表）。キーを変える＝既存の設定と記録が消える。
- 保存済みの設定値は、範囲を変えたら範囲外の値を既定に戻す（旧版の値が残るため）。

## 5. 分割・移動の手順（再発防止）
- 行を移すときは、分割前後で**行の連結が元と完全一致**することを確認してから書き出す（`1.16.1` の分割はこの方法で検証した）。
- 移した後は `regress.py` で起動時エラーと表示の一致を確認する。

## 6. 1.19系で踏んだ点
- 図柄を差し替えたのに古いまま → ブラウザ/ホストのキャッシュか、画像ファイルが未配置。今は画像をJSに埋め込んでいるので、JSが更新されれば必ず変わる。
- `pack.py` はプロジェクト直下（PEKARIKUNフォルダの中）で、`../base_<版>` を基準に実行する。外から実行すると作業フォルダ全体を固めてしまう。
- `.cabinet > .stop-row { margin:0; padding:... }` のように詳細度の高い既存規則が後付けの規則を打ち消す。効かないときは該当規則を探す。
- トロフィー通知（`.tro-wrap`）・`.at-toast` は PEKA CHANCE 中は液晶の下へ退避させている（ロゴと重ならないように）。
- 検証で `Math.random` を固定するとフェイク予告・2択予告が混ざるので、値は 0.5 にする。チェリー/スイカの予告は 1〜1.5秒レバーがロックされる。
