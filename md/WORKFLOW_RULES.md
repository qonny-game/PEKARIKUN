# 進め方のルール（ペカり君）

QNPLAYERで効果があったルールのうち、このアプリに合うものだけを残している。共通の考え方は `GOTCHAS_GENERAL.md` 側。

## 1. 依頼の受け方
- 指示語（「この部分」「バー」「ランプ」）が曖昧なら、**スクリーンショットで対象を特定**してから直す。違う部品を直すと手戻りになる。行き違いが起きたら `UI_TERMINOLOGY.md` に1行足す。
- 仕様の迷いは**既定を決めて進め、報告に「こう決めた・変えたければ言って」と書く**。取り消せない決定（公開・データ削除）だけは止まる。
- 「原因を探って」と言われたら、直す前にパラメータの意味をコードで確認する（名前と働きがズレることがある）。

## 2. 版と納品
- 版は `x.y.z`。見た目・動作を変えない整理＝z、機能追加・変更＝y。1回の納品ごとに必ず上げる。
- 版は `JS/data/config.js` の `APP_VERSION` が唯一の場所。上げたら `CHANGELOG.md` に1行足す。
- 納品は**変更ファイルだけのパッチZIP**（フォルダ構造を保つ）。`PATCH_FILES.txt` は作らない。名前は `PEKARIKUN_v<版>_patch.zip`。
- 作成：`python3 -I md/tools/pack.py <前回渡した版のフォルダ> PEKARIKUN <版> <出力先>`。前回版が無いときは `none` で完全版。
- 構成を変えた版（パスが動いた版）は、変更ファイルが実質全部になるので完全版になる。その旨を報告に書く。

## 3. 作業の順序
1. 変更前に影響範囲を読む（`FILE_MAP.md` で該当ファイルを探す。`GOTCHAS.md` を読む）。
2. 直す。変更したら `python3 -I md/tools/file_map.py` で目次とID一覧を更新する（id・保存キーを足したとき）。
3. 見た目・動作を変えない作業は、前後で `regress.py <前> <後>` を回して一致を確認する。
   例：`python3 -I md/tools/regress.py <前版フォルダ> . --spins 40`（約4分。ツールの時間制限に注意して単独で回す）
4. JSの構文は `node --check JS/<dir>/<file>.js` で確認。
5. 重いコマンドを1つにまとめない（ツール呼び出しには時間制限がある）。

## 4. ファイル構成の原則
- 読み込み順（index.html の並び）を変えない。新しい関数を他ファイルから使うときは、**トップレベルで即実行する処理から呼ぶ場合は、呼ばれる関数がそれより前のファイルにあること**（詳細は `GOTCHAS.md`）。
- 1つのファイルは役割ごとに。ファイルが大きくなったら役割で分けるが、分割は行の連結が元と一致することを確認してから書き出す。
- 外部ライブラリ・保存キー・画像/音声の名前は、互換性のため変えない（画像・音声の**場所**は `ASSET_DIR` で変えられる）。

## 5. 文言・コメント・デザイン
- **アプリ内の文言**（ラベル・説明・トースト）は簡潔・中立。砕けた口調・絵文字は使わない（チャットの口調とは別）。
- **コメント**は「注意・禁止・規約・順序依存・仕様メモ」だけ。経緯や版履歴は書かない（CHANGELOG へ）。
- 新しい部品の前に既存の部品を探す。

## 6. チャットの口調
- 友好的・タメ口。作業の報告は「何ができたか・確認したこと・未確認の点・次の選択肢」を短く。


## 演出の表示場所（1.19.17〜）
- 数字・文字・キャラが出るアニメーション（バナー・カットイン・カウント・リザルト・トースト・DON・GOGO!文字・ナビ・枚数・メーター・粒子・フラッシュ等）は、すべて演出ステージ `#lcd-stage`（演出液晶 `#sub-lcd` と同じ範囲・はみ出しは切る）の中に置く。JSで動的に作る要素も `document.getElementById('lcd-stage')` に append する（`.cab-lcd` や body には置かない）。大きさは液晶(約274x186)に収まるよう、`#lcd-stage` 配下のCSSで調整する。
- 新しい演出要素は `.cab-lcd` の子として追加する（`document.querySelector('.cab-lcd').appendChild(el)`）。CSSは `.cab-lcd > .xxx { position: absolute; inset: 0 }` の形
- 例外: 枠の色変化・リール枠の発光・サイドランプなど、液晶の外側の発光表現はそのままでよい。設定・グラフ・称号一覧などの画面（モーダル）は対象外

- パックの前に必ず `python3 -I md/tools/stamp.py` を実行する（index.html の JS/CSS に ?v=バージョンを付け、ブラウザのキャッシュで古い表示が残らないようにする）
