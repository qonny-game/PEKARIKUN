# UXレビュー手順（テンプレ）

コードの整理をするとき、ユーザーに「UXレビューも一緒にやる？」と聞いて、やると言われた場合にこの手順で回す。見た目・操作を変える提案は**報告に並べるだけ**で、勝手に直さない（決めるのは持ち主）。直すときは版を y に上げる。

## 観点
1. **操作性**: 押せる場所の大きさ（32px 以上）、押してから反応するまで、誤タップしやすい配置、スマホで親指が届くか。
2. **見た目**: 文字の大きさ（9px 未満は読みにくい）、コントラスト、同じ役割の部品の揃え方、ズレ・はみ出し・横スクロール。
3. **非効率な処理**: 常時回るタイマー（setInterval）の数と間隔、毎tickのDOM書き換え（値が同じなら書かない）、毎回の querySelectorAll、CSS の同じセレクタの重複上書き。

## 手順
1. **機械チェック**: `TW_JS=<tailwind の index.global.js> python3 -I md/tools/ux_audit.py`
   → 小さい文字・小さいタップ先・横スクロール・pageerror を PC / SP で一覧。
2. **目視**: PC 1280x800 と SP 390x844 でスクリーンショットを撮り、観点1〜2を見る（撮影は `harness_example.py` の要領で Tailwind を差し込む）。
3. **非効率の確認**: `grep -rn "setInterval\|requestAnimationFrame" JS` で常時タイマーを数え、毎tickで書き換えている箇所を探す。
4. **指摘の整理**: 下の表の形で書く。「直す」「直さない（理由）」を持ち主に決めてもらう。
5. **直す場合**: 見た目が変わる → 版は y。動作だけ変わる → y。DOMの書き換え抑制など見た目・動作が同じ → z。
6. **記録**: 下の「実施記録」に追記し、CHANGELOG に1行足す。

## 実施記録

### 1.20.55（初回）
- 機械チェック: pageerror 0件。横スクロールなし（PC・SP）。
- 小さい文字: LED の INSERT / BET 3 / REPLAY / START / WAIT が 6.5px、LEVER が 7px、PAYOUT・MEDAL・TOTAL GET（led-label）が 8px、SP の CHANCE ZONE / PEKA CHANCE が 9px 弱。
- 小さいタップ先: 上部の音・グラフ・歯車ボタンが 32×30px（もう少し大きく）。
- 重複上書き: `.pl`（LED の点灯表示）が style.css の 4箇所（約1035・1763・1777・1796行）で上書きされている。SP 幅の 6.5px がどこで効いているか追いにくい。
- 非効率: 電光掲示の同期が 50ms ごとに回る。ほかに常時タイマーが約20本（液晶の演出は 200ms〜11秒の間隔）。タブが隠れている間も回る。
- 直した（z 扱い・見た目は変えない）: 電光掲示の同期で、値が変わらないときは DOM（クラス・文字）を書かない。STOP ボタンの一覧を一度だけ集める。
- 保留（見た目に関わるので持ち主に確認）: LED の文字サイズ上げ、タップ先の拡大、`.pl` の重複整理、常時タイマーの統合・非表示時の停止。
